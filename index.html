Rules applied to this run

• Multiple sheets: upload one or several sample sheets at once — each is column-matched independently (since the qPCR header can differ per batch), then all rows are pooled together before grouping, so samples from different sheets can end up in the same pool group. If a particular file's columns can't be matched, only that file is skipped (with a note); the rest still process.

• qPCR column: its header changes per sheet (often a batch/run ID), so it's detected by content instead — whichever column's values contain a number next to "nM" wins. Triplicate values in one cell (e.g. "12.3nM, 11.9nM, 12.5nM") are averaged.

• qPCR QC: valid range is 0.9nM ≤ x < 25nM. Below 0.9nM → excluded, flagged Failed (low). 25nM or above → excluded, flagged Out of range (high).

• Material buckets: Saliva bucket = Bodily Fluid:Saliva, BODILY_FLUID_SALIVA, OTHER_BUCCAL_SWAB, Other:Buccal Swab, Saliva. Everything else pools together as one "Other" bucket. The two buckets never mix in the same group.

• Clinical priority: samples with Product = "Clinical Genome Sequencing - Technical Only v2" (either variant) can share a group with non-clinical samples, but are placed into groups first, so they fill early groups ahead of non-clinical samples.

• Molecular Index: no duplicate index within a single group. Rows with a blank index are excluded and flagged for review.

• Group size: 8–48 samples per group. Groups formed below 8 are rebalanced into earlier groups where possible; if that's not possible, they're flagged below minimum rather than silently shipped.

• Controls: identified by a blank Product field. At most one control per group; not every group needs one. A control swaps in for one non-control sample in an existing group (rather than being added on top), so the group's size — and its lane count — doesn't change.

• Coverage tier: clinical samples always target 30X. Non-clinical samples are read from the Product text (looking for "30X"/"60X"/"80X"); a Product with no coverage number is assumed 30X and flagged for review; a Product with an unsupported number (anything other than 30/60/80) is excluded and flagged.

• Group sizing: within each material bucket and coverage tier, group sizes are chosen (within 8–48) to land as close as possible to that tier's ideal lane fraction — multiples of 8 for 30X, 4 for 60X, 3 for 80X — but an exact multiple isn't required. Leftover samples just join the nearest group rather than being held out.

• Lanes don't have to be whole numbers in principle (lanes = samples × lane fraction), but physical lanes do, so the total is rounded per this rule: if the fractional remainder is at least 15% of a lane, round up (matches the reference Coverage.xlsx, e.g. 47 samples × 0.125 = 5.875 → 6). If the remainder is under 15%, round down instead of wasting most of an extra lane — e.g. 25 samples × 0.125 = 3.125 → 3 lanes, not 4.

• Lanes: for each coverage tier, lanes needed = total samples at that tier × lane fraction — always a whole number by construction. Buckets share lanes within the same tier (different index sets can be multiplexed on the same physical lane); tiers are reported separately since they need different depth.

Manifest includes pool assignments, excluded/review rows, and a summary sheet.
